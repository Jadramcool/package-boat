PacketBoat 桌面端 · 全屏布局重构

针对 1280 × 764 全屏下暴露的布局问题。实测：内容仅占 548px 高，底部塌出 216px 死区（占窗口 28%）； 主容器两侧各空 86px；驾驶舱「访问地址」输入框被拉伸到约 800px，装 190px 文本，76% 空置。 本方案用「纵向三段填满 + 驾驶舱重排 + 断点补全」解决，布局骨架不变，仅调分配规则。

1 · 现状问题拆解

MEASURED @ 1280×764

三个独立问题叠加，共同造成「全屏下不好看」的观感。

现状 · 内容塌在上半屏
216px 纵向死区 · 占窗口 28%
重构 · 纵向三段填满
问题实测数据根因
纵向 28% 死区 内容底 548px / 窗口 764px main { flex: 1 } 只被撑开、不参与分配。子元素全是 max-content，多余高度无处可去。
地址栏 76% 空置 输入框约 800px，文本约 190px .url-chip { flex: 1 } 在大宽屏下无上限，随容器无限拉伸。
两侧 86px 空边 卡片区 x=86 → 1194，宽 1108px 左右 padding 24px + max-width: 1480px 未生效（窗口仅 1280），实际边距由 padding 决定而非居中约束。
断点断层 720 → 1100px 无适配 仅设 1100px / 900px / 720px 三档，720–1100px 区间（窗口化常用尺寸）无专门布局。
视觉重心错位 二维码仅占 186px 窄条 该尺寸为小窗口设计；全屏下第一屏应是「手机怎么连上」，但二维码被挤到最右侧角落。

2 · 重构方案：全屏三段式

1280 × 764 实际渲染

骨架从 flex column 改为 grid 三段行：grid-template-rows: auto minmax(0,1fr) auto。 中段拿到 1fr 强制吸收全部剩余高度，无论窗口多高都不塌出死区；中段内部再嵌套 auto minmax(0,1fr)，让清单卡撑满、空态居中。

4 · 断点策略重构

RESPONSIVE

原三档在 720–1100px 之间没有专门布局，恰好覆盖窗口化常用尺寸。补齐为五档，并明确每档的列数变化。

档位宽度驾驶舱主区列清单列
宽屏≥ 1500px侧栏 232px1fr + 306px5 列全显
标准1100 – 1500px侧栏 232px1fr + 306px5 列全显
紧凑860 – 1100px侧栏 200px1fr + 264px隐藏「来源」
平板720 – 860px二维码转下方横排单列堆叠隐藏「修改时间」

关键点：三段式骨架在所有档位都保留（minmax(0,1fr) 在窄窗同样有效）， 只是中段内部的列数随档位塌缩 —— 因此小窗口下也不会出现「内容挤在上半屏」。
