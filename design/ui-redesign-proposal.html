PacketBoat 晴空码头 界面设计方案

设计上下文：主机端使用者是 Windows 桌面用户，核心任务是「启动服务 → 让手机连上 → 管理共享」； 发送端是局域网内任何浏览器用户（多为手机），核心任务是「输码 → 传文件 → 取文件」。 品牌人格延续现有的「局域网投递站」：直给、可靠、不经云端。方案在保留品牌基因（深海墨 × 航速绿 × Bahnschrift） 的前提下重组信息架构——把连接所需的一切收进一张「驾驶舱」卡片，其余界面做减法。

01

设计系统 ·晴空码头 Clear Harbor

延续现有品牌资产（深海墨、航速绿、Bahnschrift），做三件事：提亮底色（米黄 → 清爽船坞白）、 收窄强调色的使用范围（航速绿只给「行动与状态」，不再大面积铺底）、补全语义色（信息蓝 / 成功绿 / 危险橙各就各位）。 所有正文对比度 ≥ 4.5:1（WCAG AA），所有交互元素焦点环 3px。

04

关键变更与设计依据

方案不是推倒重来，而是保留品牌、重组信息、补齐短板。以下是相对当前版本的逐项说明。

① 连接信息整合为「驾驶舱」

现状：服务开关在页头、二维码在右侧栏、备用地址藏在下拉框，首次连接要来回找。 方案：开机 → 复制地址 → 看码 → 扫码在同一张深色卡片内完成；二维码升级为驾驶舱的固定席位。 依据：连接是这款产品的「第一次心跳」，值得独占视觉焦点。

② 色彩提亮、强调色收窄

现状：米黄底偏旧，航速绿既当按钮底又当状态色，语义不清。 方案：底色提亮为船坞白；航速绿只用于主行动与在线状态；危险（信号橙）、信息（蓝）、成功（绿）各归其位， 并为每色配「文字级深色变体」保证浅底可读（全部 ≥ 4.5:1）。

③ 文件清单信息密度优化

现状：表格五列等权，路径与状态混排。 方案：文件名自带两行（名称 + 路径/接收来源），大小 / 时间用等宽字体右对齐易扫读； 来源从纯文字升级为三态徽章（原位共享 / 远程接收 / 文件缺失），一眼可辨。 行 hover 使用航速绿 12% 洗色，与品牌一致且不抢内容。

④ 危险操作降噪但不降权

现状：「一键清空」为描边橙钮常驻，视觉权重偏高。 方案：降为「危险描边」小按钮，hover 才填充实色；保留二次确认文案 「只移除记录、不删除磁盘文件」并固化为侧栏「行为约定」卡，让用户每次都安心。

⑤ 发送页改为「三屏流」

现状：配对门、Hero 文案、货架同屏，手机上信息偏多。 方案：配对屏去 Hero、只留输入；传输屏以进度为主角（速度 / 剩余时间 / 取消）； 货架单列、触控目标 ≥ 44px。文案同步去装饰化（如「当前货架」仅在桌面端保留品牌感）。

⑥ 无障碍与动效基线

对比度全部达标（正文 ≥ 4.5:1，大字 ≥ 3:1）；焦点环统一 3px 信息蓝； 动效统一 ease-out-quart / 150–300ms，并响应 prefers-reduced-motion； 状态变化（复制成功、传输完成）同时提供颜色 + 文案 + 图标三重反馈，不单靠颜色传达。

04.1

落地建议

  1. 第一步（纯 CSS / 1 个迭代）：把本方案 token 写入 main.css 的 :root（替换现有变量即可，组件层基本兼容）。
  2. 第二步（组件级）：合并 AccessQrCard 到 DesktopHeader 形成「驾驶舱」；DesktopFileRow 增加徽章与双行文件名。
  3. 第三步（发送页）：PairingGate 改单屏大输入；UploadQueue 增加速度/剩余时间已是现有能力，仅样式迁移。
  4. 风险提示：Bahnschrift 的 SemiCondensed 字重在部分 Windows 版本需回退（方案已含回退链）；深浅两套主题建议后续用 light-dark() 扩展，本期先交付浅色。
