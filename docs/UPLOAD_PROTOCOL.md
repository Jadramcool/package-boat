# 分块上传协议

浏览器接收页使用受配对会话保护的分块协议。协议目标是让短暂断网、请求超时或页面内重试不再从零发送大文件，同时保证未完成文件不会进入共享目录。

## 流程

1. `POST /api/uploads` 创建上传会话。
2. `GET /api/uploads/{id}` 查询已确认的块。
3. `PUT /api/uploads/{id}/chunks/{index}` 上传缺失块。
4. `POST /api/uploads/{id}/complete` 原子提交完整文件。
5. 用户取消时调用 `DELETE /api/uploads/{id}` 清理会话和临时文件。

创建请求：

```json
{
  "file_name": "archive.zip",
  "file_size": 12582912
}
```

服务端响应包含 `id`、`chunk_size`、`total_chunks`、`received_chunks`、`uploaded_bytes` 和 `completed`。默认块大小为 8 MiB；客户端也可请求 256 KiB 至 16 MiB，超出范围时服务端会收敛到允许范围。

块请求体是原始二进制数据，并必须携带小写或大写十六进制 `X-Chunk-SHA256` 请求头。服务端先验证索引、精确块长度和摘要，再写入预分配临时文件的对应偏移并同步到磁盘。同一索引和摘要可以安全重试；同一索引使用不同摘要会返回 `409 Conflict`。

## 恢复与提交

客户端保留会话 ID。网络失败后重新查询会话，将 `received_chunks` 转成集合并跳过这些块。只有服务端已经验证并同步的块才会出现在集合中，因此请求中途断开不会被错误标记为完成。

提交前服务端要求所有块都已确认且临时文件长度正确，否则返回 `409 Conflict`。提交操作复用普通上传的唯一命名、同目录原子重命名和 catalog 登记逻辑，成功后通过 SSE 通知其他客户端刷新文件列表。已完成会话会短期保留，重复调用完成接口会返回同一个文件记录，不会再次创建文件。

上传会话目前保存在服务进程内存中，适用于网络中断和当前页面中的失败重试；服务重启后需要重新创建会话。浏览器刷新后也必须由用户重新选择本地文件，因为网页不能在未授权的情况下重新取得 `File` 对象。服务运行期间的过期会话和启动时发现的旧临时文件按 24 小时策略回收。

## HTTP 状态

| 状态 | 含义 |
|---:|---|
| `201` | 会话创建或文件提交成功 |
| `400` | 文件名、块索引、块长度或摘要格式无效 |
| `401` | 未配对或会话失效 |
| `404` | 上传会话不存在或已过期 |
| `409` | 块冲突或仍有缺失块 |
| `413` | 文件超过配置上限 |
| `422` | 块内容与 SHA-256 不匹配 |
| `507` | 接收目录可用空间不足 |

原有 `POST /api/files` multipart 接口继续可用，便于旧客户端兼容；新浏览器界面默认使用分块协议。
